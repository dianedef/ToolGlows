# Bug Record: BUG-2026-09-02-001

## Summary

- Title: Auto Copy leaks selected text and can copy or notify more than once
- Current status: `closed`
- Severity: `high`
- Owner: ToolGlows
- Next step: Monitor the verified Auto Copy invariant through its focused unit and isolated-browser regressions.

## Reproduction

- Preconditions:
  - Auto Copy is active, or its settings panel is opened from an inactive toolbar button.
  - A non-empty page selection exists.
- Steps:
  1. Select text with the pointer, keyboard, shortcut, or Alt element-selection mode.
  2. Observe clipboard writes, notifications, and content-script console output.
  3. Exercise a clipboard failure and open settings while the registered tool remains inactive.

## Expected Behavior

- One completed user gesture produces at most one clipboard write and one matching notification.
- Selected or formatted content is never written to diagnostics.
- Error notifications use an error state, and settings-only access does not activate page copying.
- Formatting controls operate on the selected representation they describe.

## Observed Behavior

- Raw selected and formatted content is logged.
- `mouseup`, generic `keyup`, shortcut `keydown`, and Alt `click` paths can overlap.
- Both success and error messages are emitted with success severity.
- Mounting the settings component installs global copy listeners even when the registered tool is inactive.
- Formatting starts from `Selection.toString()`, so preserved HTML structure is unavailable.

## Evidence

- Redacted static inspection of the Auto Copy composable, store, settings component, and toolbar activation boundary.
- Baseline: typecheck passed; 160 existing tests passed; no dedicated Auto Copy test was present.
- Isolated MV3 load observed the service worker; content-script interaction remained untested.
