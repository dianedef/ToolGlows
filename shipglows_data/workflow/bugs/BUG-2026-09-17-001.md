# Bug Record: BUG-2026-09-17-001

## Summary

Chrome reports an unchecked runtime error when a page holding an extension
port enters the back/forward cache. Direct, evidence-first bounded repair;
status `fix-attempted`, not browser-verified. Dates use UTC.

## Reproduction

With ToolGlows loaded in an isolated Chrome profile, open an eligible page,
navigate to another page, then go back and forward. Confirm actual BFCache
entry/restoration (for example `pageshow.persisted`) and inspect extension
errors. The supplied screenshot proves the error text, not these exact steps
or the build identity. Do not install into a personal profile automatically.

## Expected Behavior

Expected BFCache disconnects do not create unchecked errors. Unexpected
transport errors remain diagnosable. Existing bridge cleanup and reconnection
remain unchanged. A toolbar action should still communicate after restoration;
this last behavior requires real-browser proof and is not established here.

## Observed Behavior

`Unchecked runtime.lastError: The page keeping the extension port is moved into back/forward cache, so the message channel is closed.`

## Evidence

- User screenshot `chrome_464Ym24YGb.png` (Chrome error manager, unknown context).
- Installed `webext-bridge@6.0.1`: background disconnect listener cleans sessions
  without reading `runtime.lastError`; persistent-port listener reconnects
  without reading it.
- [Chrome BFCache extension messaging](https://developer.chrome.com/blog/bfcache-extension-messaging-changes)
  documents expected port closure and restored-page reconnection concerns.
- [Chrome runtime.lastError](https://developer.chrome.com/docs/extensions/reference/api/runtime#property-lastError)
  documents callback-scoped consumption. Parent agent checked official docs.
